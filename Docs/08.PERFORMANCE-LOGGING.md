# Khuôn mẫu hiệu năng và logging

## Mục đích

Tài liệu này ghi lại nguyên tắc tối ưu đã áp dụng cho MM để các project Melrandia tương lai có thể dùng lại. Mục tiêu không phải “không có query”, mà là tránh query trùng, giữ dữ liệu đúng, chỉ log tín hiệu vận hành hữu ích và không che lỗi thật.

## 1. Phân loại dữ liệu trước khi cache

Public project metadata thay đổi ít, được nhiều component đọc và không chứa secret nên phù hợp cache ngắn. Identity, authorization decision, audit, health mới nhất và dữ liệu điều khiển không dùng cache public này.

```text
Request đầu tiên
  → cache miss gate
  → SELECT public projects
  → immutable snapshot (TTL 30s)

Header/Home/Projects/Detail
  → cùng cache key
  → không query PostgreSQL lặp

Admin SaveProject thành công
  → transaction commit
  → Invalidate
  → request tiếp theo refresh snapshot
```

`SemaphoreSlim` bảo vệ cold-cache burst: nhiều request đồng thời không cùng chạy một SELECT. Double-check sau khi lấy gate tránh request đang chờ refresh lần nữa.

## 2. Vì sao vẫn cần TTL khi đã invalidate

Explicit invalidation cho phản hồi tức thời trên instance hiện tại. TTL 30 giây bảo đảm cache tự làm mới nếu database được thay đổi bởi migration, script quản trị hoặc một instance khác. TTL được giới hạn 5–300 giây bởi validator.

Cấu hình:

```json
"PortalPerformance": {
  "PublicProjectCacheSeconds": 30
}
```

Docker Compose dùng `MM_PUBLIC_PROJECT_CACHE_SECONDS`. Không đặt TTL hàng giờ cho metadata có nút Enabled/Public vì sẽ làm portal hiển thị trạng thái cũ quá lâu.

## 3. Giới hạn khi scale nhiều replica

`IMemoryCache` chỉ tồn tại trong một process. Với một Ubuntu server/một MM replica, đây là lựa chọn nhỏ và dễ bảo trì nhất. Khi chạy nhiều replica, invalidate ở replica A không xóa cache replica B; TTL vẫn giúp eventual consistency trong tối đa 30 giây.

Khi yêu cầu cập nhật đồng thời trên nhiều replica xuất hiện, thay bằng distributed/hybrid cache và pub/sub invalidation. Không thêm Redis sớm khi hệ thống chỉ có một process vì làm tăng dependency, backup, credential và điểm lỗi.

## 4. Logging có chủ đích

EF Core log `Executed DbCommand` ở Information kể cả query thành công. HTTP client handler cũng log start/send/receive ở Information. Production vận hành bình thường không cần từng câu SQL nên MM đặt:

```json
"Microsoft.EntityFrameworkCore.Database.Command": "Warning",
"System.Net.Http.HttpClient.project-health": "Warning"
```

Việc lọc này chỉ giảm console noise; không giảm số query. Cache mới là phần giảm truy vấn thật. Khi điều tra SQL, tạm override hai category về `Information` trên máy development rồi trả lại `Warning`; không bật lâu trên production vì log có thể rất lớn.

## 5. State-transition logging cho health

Một project Offline trong nhiều giờ không phải một sự kiện mới mỗi 30 giây. Monitor vẫn cập nhật `LastHealthCheckAtUtc` và response time để dashboard biết phép thử gần nhất, nhưng chỉ:

- log Warning khi `Healthy/Unknown → Unavailable`;
- log Information khi trạng thái phục hồi/chuyển khác;
- ghi audit khi trạng thái thay đổi;
- im lặng ở mức Information khi vẫn cùng trạng thái.

Cách này giữ khả năng quan sát mà tránh log storm. Nếu cần chi tiết từng poll khi debug, có thể thêm Debug log có scope riêng thay vì Warning.

## 6. Query dashboard không nên cache tùy tiện

Dashboard chạy query project cards, user count và recent audit riêng vì chúng có nhịp thay đổi khác nhau và chỉ Administrator đọc. Ba query 0–3 ms không phải N+1. Nếu số lượng lớn hơn nhiều, bước kế tiếp là đo bằng metrics/tracing rồi tối ưu projection hoặc parallel read context; không cache authorization/audit chỉ để giảm vài millisecond.

## 7. Quy tắc áp dụng cho project tương lai

1. Đo và phân loại query trước khi cache.
2. Cache read model nhỏ, immutable, không chứa secret.
3. Có TTL giới hạn và explicit invalidation sau commit.
4. Chống concurrent cache miss.
5. Không cache command/control state hoặc quyền truy cập thiếu chiến lược thu hồi.
6. Log state transition, không log cùng failure ở mỗi vòng polling.
7. Tách “ẩn log” khỏi “giảm query”; hai việc không tương đương.
8. Viết test chứng minh cache hit và invalidate trước khi dùng làm khuôn mẫu.
