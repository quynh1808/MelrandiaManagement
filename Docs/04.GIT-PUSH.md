# Hướng dẫn đưa MelrandiaManagement lên GitHub

## 1. Mục đích của tài liệu

Tài liệu này mô tả quy trình đưa toàn bộ source MelrandiaManagement từ Windows lên repository:

```text
https://github.com/quynh1808/MelrandiaManagement.git
```

Quy trình được viết cho lần push đầu tiên và những lần cập nhật sau. Mục tiêu là tránh ba lỗi phổ biến: đưa nhầm file build lên Git, ghi đè lịch sử trên GitHub và vô tình công khai mật khẩu hoặc token.

## 2. Vai trò của Git và GitHub

- **Git** là hệ thống quản lý phiên bản chạy trên máy Windows. Mỗi commit là một mốc source có thể kiểm tra, so sánh và khôi phục.
- **Repository local** là thư mục `MelrandiaManagement` trên máy đang chứa `.git` và toàn bộ lịch sử cục bộ.
- **GitHub repository** là bản source từ xa dùng để sao lưu, cộng tác và kích hoạt GitHub Actions về sau.
- **Remote** là tên đại diện cho repository từ xa. Theo quy ước, remote chính có tên `origin`.
- **Branch** là nhánh phát triển. Tài liệu dùng branch chính `main`.
- **Commit** là một gói thay đổi đã được ghi vào lịch sử Git. `git push` chỉ gửi commit, không gửi những file mới chỉ nằm trong working tree.
- **Upstream** là quan hệ theo dõi giữa `main` local và `origin/main`. Tham số `-u` thiết lập quan hệ này ở lần push đầu.

## 3. Vị trí thực hiện lệnh

Mở PowerShell và chuyển đến đúng project:

```powershell
cd C:\Users\ranca\Documents\MelrandiaSystems\MelrandiaManagement
```

Xác nhận vị trí và trạng thái:

```powershell

```

Không chạy `git add .` nếu `Get-Location` không kết thúc bằng `MelrandiaManagement`.

## 4. Kiểm tra source trước khi commit

Build và chạy test ở cấu hình Release:

```powershell
dotnet tool restore
dotnet restore --locked-mode
dotnet build MelrandiaManagement.sln --configuration Release --no-restore
dotnet test MelrandiaManagement.sln --configuration Release --no-build --no-restore
dotnet ef migrations has-pending-model-changes --context ManagementDbContext --no-build --configuration Release
```

Kết quả mong đợi là build không có error và toàn bộ test thành công. `bin/`, `obj/`, file log, `.env`, private key và certificate đã được `.gitignore` loại trừ.

Kiểm tra không có file nhạy cảm chuẩn bị được đưa lên Git:

```powershell
git status --short
git check-ignore -v .env
```

Không commit GitHub Personal Access Token, PostgreSQL/admin password, private key, file `.pfx`, `.p12`, User Secrets export hoặc `.env`. Chỉ commit `.env.example`. Nếu một token từng xuất hiện trong terminal công khai, ảnh chụp hoặc source đã push, phải revoke token đó trên GitHub và tạo token khác.

## 5. Cấu hình danh tính Git

Chỉ cần thực hiện nếu Git chưa biết tên và email của người commit:

```powershell
git config --global user.name "quynh1808"
git config --global user.email "EMAIL_GITHUB_CUA_BAN"
```

Kiểm tra lại:

```powershell
git config --global --get user.name
git config --global --get user.email
```

Email nên là email đã xác nhận trên GitHub hoặc địa chỉ `noreply` do GitHub cung cấp nếu muốn ẩn email thật.

## 6. Khai báo repository GitHub

Kiểm tra remote hiện tại:

```powershell
git remote -v
```

Nếu chưa có `origin`, thêm repository:

```powershell
git remote add origin https://github.com/quynh1808/MelrandiaManagement.git
```

Nếu `origin` đã tồn tại nhưng sai địa chỉ, sửa lại:

```powershell
git remote set-url origin https://github.com/quynh1808/MelrandiaManagement.git
```

Xác nhận:

```powershell
git remote get-url origin
```

## 7. Kiểm tra repository từ xa trước lần push đầu

Tải metadata mà chưa thay đổi source local:

```powershell
git fetch origin
git branch -a
git log --oneline --decorate --all -n 15
```

Nếu GitHub repository hoàn toàn trống, tiếp tục mục 8. Nếu `origin/main` xuất hiện, GitHub đã có commit như `README.md` hoặc `.gitignore`. Không dùng `--force` và chưa chạy `pull` khi các file local còn ở trạng thái untracked, vì Git có thể từ chối để bảo vệ file local.

Hãy tạo commit local theo mục 8 trước. Sau khi local đã có commit, hợp nhất lịch sử từ xa:

```powershell
git fetch origin
git merge origin/main --allow-unrelated-histories
```

Nếu có conflict, mở từng file được Git báo, chọn nội dung đúng, sau đó chạy:

```powershell
git add <duong-dan-file-da-xu-ly>
git commit
```

## 8. Tạo commit đầu tiên

Đưa file vào staging:

```powershell
git add .
```

Phải xem lại danh sách trước khi commit:

```powershell
git status --short
git diff --cached --stat
git diff --cached
```

Nếu không có secret, file build hoặc thay đổi ngoài dự kiến, tạo commit:

```powershell
git commit -m "Initial MelrandiaManagement portal"
git branch -M main
```

## 9. Đăng nhập GitHub an toàn trên Windows

Với Git for Windows, khi chạy `git push`, Git Credential Manager thường mở trình duyệt để đăng nhập. Đây là cách ưu tiên vì không cần ghi token trong source hoặc lịch sử PowerShell.

Nếu đã cài GitHub CLI, có thể dùng:

```powershell
gh auth login
gh auth status
```

Chọn `GitHub.com`, giao thức `HTTPS` và đăng nhập bằng trình duyệt. Không dùng lệnh `echo "ghp_..."` và không lưu token vào file trong project.

## 10. Push lần đầu

```powershell
git push -u origin main
```

Sau khi thành công, kiểm tra:

```powershell
git status
git branch -vv
git log --oneline --decorate -n 10
```

`git status` cần hiển thị working tree sạch và branch `main` theo dõi `origin/main`.

## 11. Quy trình cập nhật những lần sau

Trước khi bắt đầu sửa source:

```powershell
git pull --rebase origin main
```

Sau khi sửa và kiểm tra build/test:

```powershell
git status --short
git add .
git diff --cached --stat
git commit -m "Mo ta ngan gon thay doi"
git push origin main
```

`pull --rebase` đặt commit local mới lên trên commit mới nhất của GitHub, giúp lịch sử tuyến tính. Không dùng rebase khi đang có thay đổi chưa commit; hãy commit hoặc stash trước.

## 12. Xử lý lỗi thường gặp

### `src refspec main does not match any`

Branch chưa có commit. Chạy `git add .`, `git commit`, `git branch -M main`, rồi push lại.

### `remote origin already exists`

Không thêm remote lần nữa. Dùng:

```powershell
git remote set-url origin https://github.com/quynh1808/MelrandiaManagement.git
```

### `repository not found` hoặc `permission denied`

Kiểm tra URL bằng `git remote -v`, xác nhận repository tồn tại và tài khoản đăng nhập có quyền Write. Sau đó đăng nhập lại bằng Git Credential Manager hoặc `gh auth login`.

### Push bị từ chối vì `non-fast-forward`

GitHub có commit mới mà local chưa có. Không dùng `--force`. Chạy:

```powershell
git pull --rebase origin main
git push origin main
```

Nếu đây là hai lịch sử độc lập ở lần đầu, dùng quy trình `--allow-unrelated-histories` tại mục 7 thay vì rebase.

### Local changes bị ghi đè khi pull

Kiểm tra thay đổi:

```powershell
git status
git diff
```

Ưu tiên commit phần đã hoàn chỉnh. Nếu chỉ cần cất tạm:

```powershell
git stash push -u -m "tam-cat-truoc-khi-pull"
git pull --rebase origin main
git stash pop
```

Sau `stash pop`, phải kiểm tra và xử lý conflict trước khi tiếp tục.
