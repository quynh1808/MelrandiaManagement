# Thiết lập PostgreSQL riêng cho MelrandiaManagement

## 1. Mục đích, lý do và phạm vi

MM cần persistence cho tài khoản, role, Project Registry, quyền theo dự án và audit log. Những dữ liệu này có quan hệ rõ ràng và cần unique constraint/transaction, vì vậy PostgreSQL phù hợp hơn file JSON hoặc catalog in-memory.

Tài liệu dùng PostgreSQL 17. AMS và MM có thể chạy cùng một PostgreSQL cluster nhưng phải dùng database và application role khác nhau:

```text
PostgreSQL cluster :5432
├─ aquaculture_monitoring   ← AMS sở hữu
└─ melrandia_management     ← MM sở hữu, role melrandia_app
```

Không xóa, rename hoặc cho `melrandia_app` quyền trên database AMS. “Database riêng” ở đây là ranh giới logic và credential riêng; trên production có thể dùng chung process PostgreSQL nếu tài nguyên máy chủ còn phù hợp.

## 2. Thuật ngữ cần biết

- **PostgreSQL server/cluster**: process quản lý nhiều database và lắng nghe mặc định TCP 5432.
- **Database**: không gian dữ liệu độc lập trong cluster, ở đây là `melrandia_management`.
- **Role**: danh tính PostgreSQL. Role `melrandia_app` chỉ dành cho ứng dụng MM; không dùng superuser `postgres` để chạy app.
- **Schema**: namespace bên trong database. MM dùng schema `public` và EF tạo table tại đây.
- **Connection string**: Host, Port, DatabaseName, Username và Password để app kết nối.
- **EF Core migration**: source có phiên bản mô tả cách tạo/nâng schema; file nằm trong `Migrations/`.
- **Bootstrap admin**: account portal được tạo đúng lần đầu khi chưa có Administrator; nó khác PostgreSQL role.
- **Readiness**: `/health/ready` chỉ trả thành công khi MM kết nối được database.

## 3. Cài trên Windows 10/11

### 3.1. Chọn thành phần installer

Khuyến nghị PostgreSQL 17 x64. Trong installer giữ:

- PostgreSQL Server: bắt buộc;
- Command Line Tools: bắt buộc để có `psql`;
- pgAdmin 4: nên cài để xem database bằng giao diện;
- Stack Builder: không cần cho MM. Nếu installer bắt chọn category trong Stack Builder, có thể đóng Stack Builder vì đây chỉ là trình tải extension/driver bổ sung, không phải bước tạo server.

Giữ port 5432 nếu chưa bị service khác dùng. Ghi lại password của PostgreSQL superuser `postgres`; password này chỉ dùng quản trị và không đưa vào appsettings/Git.

### 3.2. Kiểm tra service và TCP

Mở PowerShell:

```powershell
Get-Service -Name "postgresql*"
Test-NetConnection 127.0.0.1 -Port 5432
```

Kết quả cần có `Status = Running` và `TcpTestSucceeded = True`. Nếu service dừng:

```powershell
Start-Service postgresql-x64-17
```

Lệnh `Start-Service` có thể cần PowerShell “Run as Administrator”. Nếu `psql` chưa ở PATH, dùng đường dẫn đầy đủ:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" --version
```

### 3.3. Tạo role và database bằng script trong source

Chuyển tới repo và mở `psql` bằng superuser:

```powershell
cd C:\Users\ranca\Documents\MelrandiaSystems\MelrandiaManagement
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -p 5432 -U postgres -d postgres -W
```

`-W` yêu cầu nhập password `postgres`. Tại prompt `postgres=#`, nhập:

```text
\i postgres-init/create-management-database.sql
\password melrandia_app
\q
```

`\password` yêu cầu nhập password hai lần và không echo; psql tạo câu `ALTER ROLE` an toàn nên password không nằm trong command history hoặc source. Script tạo role/database nếu thiếu và giao schema cho role ứng dụng. Chạy lại `\password melrandia_app` là thao tác rotate password có chủ đích; sau đó phải cập nhật User Secrets của MM.

Kiểm tra bằng chính role app:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -p 5432 -U melrandia_app -d melrandia_management -W -c "select current_database(), current_user;"
```

Kết quả phải là `melrandia_management | melrandia_app`.

### 3.4. Lưu secret development ngoài Git

Project có `UserSecretsId`, vì vậy dùng Secret Manager:

```powershell
dotnet user-secrets set "PostgreSql:Password" "PASSWORD_MELRANDIA_APP"
dotnet user-secrets set "BootstrapAdmin:Password" "PASSWORD_ADMIN_MANH"
```

Password admin phải ít nhất 12 ký tự, gồm chữ hoa, chữ thường, số và ký tự đặc biệt. Có thể override username/URL AMS:

```powershell
dotnet user-secrets set "BootstrapAdmin:Username" "admin"
dotnet user-secrets set "InitialProjects:AmsPublicUrl" "http://192.168.100.66:8080"
dotnet user-secrets set "InitialProjects:AmsHealthUrl" "http://192.168.100.66:8080/health/ready"
```

Kiểm tra tên key mà không in value:

```powershell
dotnet user-secrets list | ForEach-Object { ($_ -split ' = ')[0] }
```

### 3.5. Migration, chạy app và đăng nhập

```powershell
dotnet tool restore
dotnet restore MelrandiaManagement.sln --locked-mode
dotnet ef migrations list --context ManagementDbContext
dotnet ef database update --context ManagementDbContext
dotnet run --project MelrandiaManagement.csproj
```

`AutoMigrate=true` cũng tự áp migration khi startup; chạy `database update` thủ công giúp thấy lỗi trước khi khởi động UI. Mở:

`dotnet ef` đọc cùng `appsettings.json`, User Secrets và biến môi trường như MM. Nếu User Secrets chưa có `PostgreSql:Password`, model-only command vẫn chạy bằng placeholder nhưng `database update` sẽ bị PostgreSQL từ chối; vì vậy phải hoàn thành mục 3.4 trước.

Danh sách migration phải có `InitialManagementSchema`, `AddArticlePublishing` và `AddArticleConcurrencyControl`. Migration thứ hai tạo category/article/media metadata; migration thứ ba ghi nhận EF concurrency token và có `Up/Down` trống vì không đổi cột PostgreSQL. File ảnh thật không nằm trong PostgreSQL mà nằm tại `App_Data/media` trên Windows.

```text
http://localhost:5106/health/live
http://localhost:5106/health/ready
http://localhost:5106/login
```

Đăng nhập `admin` bằng password bootstrap. Lần chạy sau có thể xóa secret bootstrap nếu database đã có Administrator; app không dùng nó để reset account đã tồn tại.

### 3.6. Xem bảng bằng psql

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -U melrandia_app -d melrandia_management -W
```

Trong psql:

```text
\dt
select "UserName", "DisplayName", "IsEnabled" from users;
select "ProjectKey", "HealthStatus", "PublicUrl" from projects order by "DisplayOrder";
select "MigrationId" from "__EFMigrationsHistory";
\q
```

Không sửa trực tiếp password hash hoặc xóa record Identity. Thay đổi nghiệp vụ qua UI/service để giữ validation và audit.

## 4. Ubuntu Server 24.04 LTS bằng Docker Compose

### 4.1. Chuẩn bị `.env`

```bash
cd /opt/melrandia/MelrandiaManagement
cp .env.example .env
chmod 600 .env
nano .env
```

Thay mọi chuỗi `replace-with-*`. Tạo password ngẫu nhiên, ví dụ:

```bash
openssl rand -base64 36
```

Không thêm khoảng trắng quanh dấu `=` và không thêm comment sau value trên cùng dòng. Nếu value chứa ký tự `#` hoặc khoảng trắng, đặt toàn value trong dấu nháy kép.

### 4.2. Ý nghĩa database trong Compose

Service `postgresql` dùng `postgres:17-bookworm`; ba biến `POSTGRES_*` chỉ tạo database/role khi volume còn trống. Sau khi volume đã có dữ liệu, đổi `.env` không tự đổi password trong PostgreSQL. Nếu cần rotate, phải chạy `ALTER ROLE` có kiểm soát và cập nhật `.env` cùng thời điểm.

PostgreSQL chỉ nối mạng `backend` internal và không publish 5432 ra LAN. Container MM nối cả `backend` để vào database và `frontend` để gọi health AMS. Dữ liệu quan hệ nằm ở named volume `management_postgresql_data`; ảnh bài viết nằm ở `management_article_media`; Data Protection key nằm ở `management_data_protection_keys`. Ba volume có vòng đời độc lập với image/container.

### 4.3. Pull và chạy

Đăng nhập GHCR nếu package private bằng token chỉ có `read:packages`, sau đó:

```bash
docker login ghcr.io -u quynh1808
./scripts/deploy-ubuntu.sh "sha-<FULL_COMMIT_SHA>"
```

Hoặc chạy từng bước:

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=150 management postgresql
```

`MM_BIND_ADDRESS` nên là IPv4 tĩnh của Ubuntu nếu máy khác trong LAN cần truy cập; ví dụ `192.168.100.66`. Không dùng IP có trạng thái `DOWN` trong `ip -br -4 address`. Port mặc định MM là 8090 để không đụng AMS 8080.

Kiểm tra từ Ubuntu bằng địa chỉ thật đã đặt trong `.env` (không gõ nguyên ký hiệu `${...}` và không `source .env` như shell script):

```bash
curl -fsS http://192.168.100.66:8090/health/live
curl -fsS http://192.168.100.66:8090/health/ready
```

Từ máy Windows cùng LAN mở `http://192.168.100.66:8090/login`.

### 4.4. Backup và restore

Backup logical không chứa password trong lệnh:

```bash
docker compose exec -T postgresql pg_dump -U "$MM_POSTGRES_USERNAME" -d "$MM_POSTGRES_DATABASE" -Fc > mm-$(date +%F).dump
```

Nếu đã có bài viết, phải backup thêm media volume ở cùng mốc thời gian:

```bash
docker volume ls | grep management_article_media
mkdir -p backups
docker run --rm -v melrandia-management_management_article_media:/source:ro -v "$PWD/backups:/backup" alpine:3.22 tar -czf /backup/mm-article-media-$(date +%F).tar.gz -C /source .
```

Thay tên volume bằng kết quả thực tế của `docker volume ls`. File dump chứa account hash/audit; media có thể có bản quyền hoặc dữ liệu cá nhân. Cả hai phải hạn chế quyền, mã hóa, lưu ngoài server và được quản lý như một backup set. Thử restore database **và** media trên môi trường kiểm thử trước; không xem backup là an toàn nếu chưa diễn tập khôi phục.

## 5. Lỗi thường gặp

### `TCP 127.0.0.1:5432` không chạy được

`TCP ...` không phải lệnh. Dùng `Test-NetConnection` trên PowerShell hoặc `pg_isready`/`psql`. Kiểm tra service, port và firewall theo mục 3.2.

### `password authentication failed for user melrandia_app`

Password trong User Secrets/`.env` khác password PostgreSQL role. Chạy lại script bằng superuser để đặt cùng password, sau đó restart MM. Không đổi password chỉ trong appsettings.

### `database melrandia_management does not exist`

Chưa chạy script tạo database hoặc Compose volume được tạo với tên database cũ. Xem log PostgreSQL; không xóa volume production để sửa lỗi này.

### `Database chưa có Administrator`

`BootstrapAdmin:Password`/`MM_BOOTSTRAP_ADMIN_PASSWORD` đang trống. Đặt secret đủ policy rồi chạy lại. Nếu admin đã tồn tại nhưng quên password, không xóa bảng; cần quy trình reset account có audit ở giai đoạn security tiếp theo.

### Đổi Bootstrap password nhưng vẫn không đăng nhập được

Bootstrap chỉ tạo account khi database chưa có Administrator và không reset password đã tồn tại. Dùng recovery cục bộ, không xóa bảng `users`:

```powershell
dotnet user-secrets set "AdminRecovery:Username" "admin"
dotnet user-secrets set "AdminRecovery:Password" "MAT_KHAU_MOI_DU_POLICY"
dotnet run --project MelrandiaManagement.csproj -- reset-admin-password
dotnet user-secrets remove "AdminRecovery:Password"
```

Lệnh chỉ chấp nhận account có role Administrator, dùng Identity password reset, mở khóa account, reset số lần sai, rotate security stamp và ghi audit. Secret recovery phải xóa ngay sau khi dùng.

### `/health/live` OK nhưng `/health/ready` lỗi

Process đang chạy nhưng không kết nối được PostgreSQL. Kiểm tra Host (trong Compose phải là `postgresql`, không phải `localhost`), port, database, role, password và log migration.

### Antiforgery token không giải mã sau redeploy

Data Protection keys không được persist hoặc volume sai quyền. Compose có service `data-protection-init` và volume `management_data_protection_keys`; không xóa volume này khi chỉ cập nhật image. Cookie cũ có thể cần xóa một lần nếu key ring đã mất.

### Upload ảnh báo không có quyền ghi

Kiểm tra `data-protection-init` đã hoàn tất và volume `management_article_media` được mount tại `/app/App_Data/media`. App chạy UID 1654 nên không sửa bằng cách chạy app container dưới root. Chạy `docker compose logs data-protection-init management` để tìm lỗi quyền, sau đó sửa owner của đúng volume thay vì `chmod 777`.

## 6. Checklist hoàn tất

- PostgreSQL 17 chạy và port kiểm tra thành công.
- Database `melrandia_management` thuộc role `melrandia_app`.
- MM không dùng role superuser và không dùng database AMS.
- Password chỉ nằm trong User Secrets hoặc `.env` mode 600.
- Cả ba migration `InitialManagementSchema`, `AddArticlePublishing`, `AddArticleConcurrencyControl` có trong history.
- `/health/live` và `/health/ready` cùng thành công.
- Đăng nhập admin chuyển đúng tới `/Management`.
- Volume PostgreSQL, Data Protection keys và article media không bị xóa khi deploy image mới.
- Backup/restore PostgreSQL và article media đã được diễn tập cùng nhau.
